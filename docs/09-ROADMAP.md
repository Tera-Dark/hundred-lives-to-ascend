## 优先评审问题（先问是否好玩，再问可否开发）
1. **一年如何流逝？** 自动推进 + 主动动作耗年会否造成操作过频或等待？如何暂停重大事件？
2. **轮回点最优策略？** 长轮回、早退轮回、首次达标、稀有遗泽是否有公平竞争。
3. **系统最小耦合？** 修行、机缘、备劫之间至少哪两条选择路径能改变天劫成绩？
4. **天劫可读性？** 玩家失败时能否知道如何改善，是否可以部分过关得到阶段奖励？
5. **前 3 世惊喜？** 是否有可感知解锁，不只是第 1 世内容快速重复。
6. **逐步解锁是否拖沓？** 系统渐进需要解决认知负担，不能用空刷轮回次数代替教学。
7. **数值/存档健壮性？** 大数溢出、事件种子、后台年限、档案迁移怎么保障。

## MVP 暂不做
大地图自由走动、完整宗门 3D 经营、多人、多人 PvP、拍卖经济、大型开放世界、复杂御剑战斗手操、数百条功法、跨界全剧情、离线自动战胜大劫、付费充值与强制广告。

## 开发前验收门槛
- 提供至少两种首世可行构筑思路，不能全靠同一倍率最优；
- 没有永久进度被单次随机事件彻底卡死；
- 每世大劫三个阶段有明确机制差异及失败反馈；
- 轮回点奖励对短/长轮回的取舍可解释；
- 前几次轮回的质变节点与新功能均有“为什么此时解锁”的理由；
- 游戏逻辑能够在没有 Cocos 的条件下被自动模拟；
- 存档、广告资格、TapTap 运行环境核验列入开发准备。

## 变更流程
提出想法 → 标明所属权威文档及受影响系统 → 说明对玩家的价值和代价 → 文档草案更新 → 用户评审 → 冻结 PRD → 才允许正式开发。非关键创意可进入未来内容池，不能自动升级为 MVP 必做。
