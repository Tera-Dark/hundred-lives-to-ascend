# 06 · 竖屏 UI、美术与时间压力表达 V0.4

## 一、设计原则
面向 TapTap 手机端，清雅东方玄幻、低饱和雾白/黛青/浅金，红色仅用于“性命危险/纪元斩杀线”。**同一屏同时看清：我的年龄、寿限、当前境界、世界年份、下一场危机与可执行目标**。不要做十几层升级分支。

## 二、首页布局（9:16 草图）
```text
┌──────────────────────────────────┐
│ 第3世  92/240岁  · 筑基中期      │ ← 主角寿元（主要压力）
│ 寿元剩余148年   世界历 143年     │ ← 世界年独立显示
│ 下场纪元杀劫：160年  剩17年  !  │ ← 第二压力与预警
├──────────────────────────────────┤
│          山水/人物/境界视觉       │
│  修为 31.2万 / 50万  +1200/秒    │
│          [闭关] [突破]           │
├──────────────────────────────────┤
│ 当前目标：准备应对黑潮渡关       │
│ 生路一：筑基护体进阶  进度 65%    │
│ 生路二：与天衡司结盟  进度 20%    │
│ ✨前世遗藏：旧纹护心玉可寻回      │
├──────────────────────────────────┤
│ [修行]   [机缘]  [应劫]  [轮回]  │
└──────────────────────────────────┘
```
数字纯属UI示例；年龄、寿限与世界时间的实际进度以 05/10 测试结果为准。

## 三、双时钟视觉优先级
1. **寿命**在顶部固定显示 `年龄 / 当前寿限`，寿元不足时使用有克制的危险提示；突破延寿时明确演示寿限增长。
2. **纪元**同时显示世界历与下一处生存关口的**剩余世界年数**，不是当前角色距第100年的倒计时。若无近端危险，收起为轻量历法。
3. **危机预告**用小卡片列出危险机制与至少两种生路，显示“已满足 / 还缺什么”，不把“必死”偷偷藏在二级页面。
4. **轮回**让玩家看到生卒年份与寿龄、世界线是否延续、被留在世间的实体物品与下世找回地点。
5. **前世遗藏**作为“机缘”中可见的线索卡，重点显示“前世留下”“可寻回”“需要几年/什么条件”，不独立占一个导航栏。

## 四、交互细节
- 固定底部 4 个主入口：修行 / 机缘 / 应劫 / 轮回；新子系统仅在对应入口展示。
- 不可逆选择（突破赌寿、主动转世、纪元锚点回溯、危险秘境探索）先暂停游戏时间，展示后果和确认。
- 在同一世界线将发生致命灾劫前，提前提供窗口与替代方案；长寿角色渡过关口要表现“活过时代”的里程碑。
- 发现前世遗物使用简短专属音画与世录：“上世封存的旧纹护心玉，仍在此处”；不靠十秒以上不可跳过的动画。
- 转世后世界年递进导致历史改变时，应突出最新世界史摘要，而不是让玩家阅读数十段日志。
- 时间可暂停/调整速度；后台恢复默认不越过死亡/斩杀线。手机刘海、圆角和手势安全区必须测试。

## V0.3 多篇章与三阶传承的界面策略
- 四个主入口仍固定为「修行/机缘/应劫/轮回」；**篇章选择嵌入轮回页**，不增设第五个永久大按钮。
- 开场不显示 DP/EP 货币。化神证道解锁道果页签，飞升后解锁界源页签；不以几十个锁定节点占满首页。
- 纪元篇章切换采用清晰的卡片：历史主题、特殊生存门槛、预计难度、首通奖励、进入后保留/丢失哪些状态。
- 传承页面优先显示“下一笔值得买的功能升级”，给倍率/自动化/新系统三种过滤；玩家首次看到高阶法则要有可视化的新能力演示。
- 旧篇章世界线回访显示「已封存、历史停止推进、旧物仍保存在此」，避免玩家以为永久丢弃前世物品。

## V0.4 一局低操作密度约束
- 主界面默认 **1个当前主目标 + 最多2个可执行次级动作**；简单修行与生产无需逐项点“领取”。
- 关键选择触摸不超过2步可确认（点卡片→确认）；危险操作保留明确二次确认，但不引入多层菜单。
- 一次只放一张必须处理的事件卡，展示耗费几年、资源缺口、失败风险；阅读期间暂停游戏年。
- 若历史第60年已发生，主界面改为「灵潮余波」或下一目标，而不是提示玩家再去防御过往的灾劫。
- 早期轮回商店只展示4–6个已解锁/可见的有意义节点，后期DP/EP页签仍隐藏。
- 体验节奏与UI点击预算权威见 [17](17-SESSION-PACING.md)，逻辑纸面走查见 [18](18-PAPER-PLAYTEST.md)。

## 五、可及性与性能
- 常用按钮有足够触控热区（设计目标约 44–48 逻辑单位，经实际分辨率校正）。
- 支持数字大数简写与查看精确值、字体缩放/高对比度、低动画与音效关闭。
- Cocos 2D UI 为主，突破、轮回、世界事件用少量动效；不为文字增量游戏增加大量真实物理和复杂 3D。
- 不将任何广告按钮放在“死亡确认”“寿尽警告”“关口逃生”主操作附近，防止误触。
