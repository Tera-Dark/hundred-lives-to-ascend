## 一、构建与执行
- HTML/CSS + JavaScript ES Modules，纯前端无依赖，GitHub Pages可以静态服务，无服务端账号接口。
- 本地：仓库根目录 `python -m http.server 8000 -d prototype` → 浏览器打开 `http://localhost:8000/next/`。
- 测试：`node --test prototype/next/tests/*.test.mjs`；**19项状态机测试全部通过**。
- 数据在本地`localStorage`键`bsjl-v12-current`，旧MVP-0独立；第160世界年当前原型安全暂停。
- GitHub Pages发布源预置`gh-pages`分支，根路径跳转新版；**仓库设置是否完成Pages启用、正式公网是否可访问需以实际网页为准**。
- 本轮尝试了无头浏览器自动检查，但该环境阻拦本地HTTP/file导航，**不得写“已通过真实Chrome UI端到端测试”**。

## 三、测试覆盖
**通过的19项包括：** 时间份额的经营/修行/研习取舍、职业晋升和材料收入、生活投资提高效率、法门解锁；玄×商/药与丹×商/药四组固定策略存在生存路线；跨世界灾劫动作截止、世界年60仅一次；职业纪录与财产重置、NPC真实老化与旧约跨世影响、无约定就不能领旧约权益；真实实物ID唯一、世界年95只结算一次、存档恢复、RP购买、两槽不可重复、跨年动作遇事件先停、160安全停止、两出身差异、商路留存收益。

这些是**明确边界测试**，不代表4组合随机玩家胜率为100%、所有操作都能正确或玩家实际觉得有趣。

## 四、旧版参数不能沿用
旧固定每年灵石+2、凡人15/炼气28/学专注40等模型在 [19](19-FIRST-CHAPTER-ECONOMY.md) 是旧样本。V1.2改为`年工资 = 职业全职工资×工作份额×地点及研究状态`，`年修为 = 境界基率×修行份额×生活/功法/灵藏`，同时日常维护从现金净流里扣除。跨年强行动覆盖全部计划，不能又领满额工作工资/修行。

**这说明旧表里的“第53年筑基”不再是新版可玩结果**。本版固定策略能过首劫，但目前未做玩家大规模策略搜索、价格曲线最优化或长寿收益的完整平衡。

## 五、必须通过人工试玩观察的体验问题
1. 玩家是否在前1–2分钟理解职业/出身和修行道途分开？
2. 职业 Lv5 是不是真正能感觉到的工资跃升；是否愿意主动购买灵食改善效率？
3. 中段会不会只是不停点“五年/下一节点”，缺少需要改变计划的机缘？
4. 选NPC有价合作时，愿不愿意牺牲2年和材料；第二世历史后果是否明显？
5. 玩家是否理解灵藏图谱与前世实际护心玉有区别？
6. 自动化解锁后是否减轻微操；主修两条是否仍是不同策略？
7. 移动端信息密度与误触、存档兼容、无头浏览器受限以外的UI问题，都还未完成真机验收。

**下一个最小改进优先级：先修真实试玩反映的阻碍，再扩NPC三幕/后人剧情；不要现在增加大量杂项系统。**
